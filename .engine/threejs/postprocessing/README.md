# Bounded Three.js postprocessing starter

`postprocessing-runtime.mjs` uses the host's exact Three 0.182.0 and postprocessing 6.39.5 libraries. `createPostprocessingRuntime` owns one LDR byte-buffer composer per renderer: scene RenderPass followed by FXAA EffectPass, with depth and zero MSAA. It preserves Quarks in the raster scene and never replaces the renderer, installs packages, starts another animation loop, changes color/tone settings or selects path tracing.

Supply the actual host renderer, Scene, Camera and fresh THREEJS engine selection. The renderer must expose an actual branded WebGL2 context, SRGBColorSpace and NoToneMapping. Construction probes completeness of both actual bounded byte/depth framebuffers while restoring the prior target/cube/mip bindings. Missing/lost context, unsupported profile and unavailable framebuffer fail explicitly. An API or framebuffer check does not establish shader, visual, performance or packaged MAUI acceptance.

Use `render(deltaSeconds)` once per host presentation frame after scene/Quarks updates. Delta is explicit and bounded (default 0.1s, configurable at most 0.25s); no private clock/RAF is advanced. The default physical pixel budget is 1920x1080, dimension ceiling 4096 and DPR ceiling 2; never multiply logical dimensions by DPR before `resize(width,height,pixelRatio)`. It updates logical size and DPR together, then uses the composer's actual drawing-buffer size. Canvas CSS, camera aspect/projection and game layout stay with the host. Initial renderer dimensions must already fit the budgets.

`pause/resume`, MAUI `opencaw:lifecycle` events and document visibility suppress rendering independently. Context loss prevents rendering; restoration requires explicit `revalidate()` before either resizing or rendering. A resize cannot clear this restoration gate or reuse stale device limits. The helper rechecks current context/profile/dimensions and real framebuffers. A changed context identity needs disposal/recreation. Revalidation reports shader/visual/native acceptance as unverified. No automatic quality/backend fallback exists.

`inspect()` exposes current bounds, frames, suspension and readiness limits. `dispose()` is idempotent, removes listeners and releases owned passes/effects, targets, copy pass and timer, restoring borrowed renderer autoClear. The pinned upstream composer's general `dispose()` also disposes module-shared fullscreen geometry; this helper deliberately preserves that borrowed geometry for other composers. At final application teardown, after **all** composer/pass users from that package instance are retired, the application owner must call `Postprocessing.Pass.fullscreenGeometry.dispose()` before `renderer.dispose()`; renderer disposal alone does not dispatch geometry-disposal events. The exported static getter is available in the pinned package but marked internal upstream, so recheck this cleanup boundary when changing versions. Scene, camera, materials, textures, particles and renderer are never disposed here. Do not share this runtime's owned passes/effects or mutate renderer settings/size behind it. Custom passes, HDR/bloom/depth effects, XR, MSAA, other versions and other renderer profiles require a separately reviewed integration and target evidence.

The tests execute actual package CPU APIs with clearly labeled browser-context/renderer fixtures. They do not create a GPU context, compile shaders or run a native MAUI application.

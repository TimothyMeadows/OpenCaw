# Non-authorizing AUDIO templates

These examples grant no setup, generation, review, distribution or promotion. Zero hashes intentionally cannot identify real evidence. Copy a brief into the active task's owned input area, replace paths/hashes with applicable existing evidence and validate it through `audio-pipeline.sh brief --root ROOT --brief FILE` before initialization. Obtain any missing permissions separately. Do not edit a used immutable brief or accepted original; create a new version with ancestry.

`brief.local.json` uses actual Bubo settings, maximum* budget names and item seconds. Backend selection and version-owned request/output IDs belong to the pipeline, not caller overrides. Native rights are a bubo-media-rights/v1 declaration; the installation receipt points to current applicable license assertions. Planning/import can retain original-task rights without granting new generation. Actual dispatch requires current-task generationAllowed:true and native full installation admission.

`brief.cloud.json` describes import of separately authorized session media, with no local installation or diffusion controls. The command does not provide unattended CLOUD generation or pretend missing analysis is available. Imported CLOUD output remains technically ineligible until a supported compatible analysis capability is selected; no LOCAL fallback occurs.

An optional LOCAL `historicalRoot` supports metadata import from an existing original root strictly below the current project. Keep new brief rights/installation identities canonical to the current project and preserve original JSON unchanged. The neutral wrapper must name the same historicalRoot, raw source/result/context/manifest identities and actual original revision evidence. The original context.projectRoot must still resolve to that declared directory. This does not retarget another machine's paths and is forbidden for new generation. Supplied model catalogue snapshots retain exact native catalogue hashes; do not replace original runtime/model identities with current pins.

The review examples deliberately say rejected and contain no output identities. Actual content acceptance binds the current composite assetSha256 and entire ordered output set, human source, reviewer, reason and AUDIO criteria. Intended loops require actual seam review. Actual runtime acceptance additionally references an opencaw-audio-distribution/v1 record (`task`, matching `purpose`, `rightsConfirmed:true`, typed `sourceEvidence`) and opencaw-audio-runtime-evidence/v1 (`task`, current `engine`, exact `outputs`, matching `spatialization`/`loopIntent`, actual `playbackReviewed`, `loadDisposeReviewed`, applicable `loopSeamReviewed`, typed `sourceEvidence`). These are explicit source assertions, not automatic inference from metrics.

Use the shared handoff/promotion authorization formats only after actual reviews. Runtime promotion is a separate explicit operation; neither an example, source merge nor backend QA approval authorizes it.

# Capture Ui Reference Pack

## When to use

- Researching several interfaces before design work.
- Capturing responsive, animated, lazy-loaded, or stateful pages.
- Creating a durable evidence bundle for another role.

## Workflow

1. Define the research question, target audience, comparison categories, and allowed sources.
2. Record each source URL, capture time, viewport, visible state, and access limitation.
3. Capture full-page and focused evidence with `capture-full-page-evidence` where needed.
4. Describe hierarchy, spacing, typography, color, imagery, interaction, motion, accessibility, and performance signals.
5. Mark distinctive expression that should not be carried into new work.
6. Synthesize transferable principles and unresolved questions.

## Output

- A source registry and evidence manifest.
- Annotated capture paths with viewport and state metadata.
- A concise pattern matrix separating reusable grammar from distinctive elements.

## Guardrails

- Do not capture authenticated or private material without explicit authority.
- Do not store credentials, cookies, or personal account data.
- Do not turn the pack into a mandate to reproduce a source.

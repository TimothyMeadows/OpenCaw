# Prototype From Reference Pack

## When to use

- Exploring multiple product directions from visual research.
- Testing alternative layouts or interaction approaches before production.
- Creating comparable prototypes with a shared acceptance framework.

## Workflow

1. Validate that the reference pack identifies sources, transferable patterns, and distinctive exclusions.
2. Define one product goal and an originality matrix for each prototype.
3. Give every prototype a different structure, identity system, content strategy, and interaction emphasis.
4. Build each prototype in an isolated scope using the host architecture and active style contract.
5. Validate accessibility, responsive behavior, interaction completeness, console health, and reference distance.
6. Report the prototypes as experiments; do not publish or deploy without separate authority.

## Output

- One decision-complete brief per prototype.
- A comparison matrix covering intent, differences, risks, and validation.
- Local artifact paths and a recommendation for further development.

## Guardrails

- Do not reuse source brands, copy, people, claims, pricing, or media.
- Do not create autonomous tasks, commits, deployments, or publications.
- Do not hide missing behavior behind static screenshots.

# Design Web Experiences

## When to use

- Designing or redesigning a complete web experience.
- Coordinating art direction, content, motion, interaction, and frontend execution.
- Reviewing whether a page feels coherent and production-ready.

## Workflow

1. Read the active architecture and style contracts, then define audience, intent, primary action, content proof, and performance budget.
2. Establish visual tokens for type, color, spacing, surfaces, imagery, grid, and states.
3. Compose the page around a clear narrative and responsive hierarchy.
4. Add motion and interactive effects only when they improve comprehension, orientation, or feedback.
5. Specify semantic structure, keyboard paths, reduced motion, contrast, loading, failure, and no-script fallbacks.
6. Validate real content, responsive states, accessibility, runtime health, and implementation feasibility.

## Output

- An art-direction and page-system brief.
- Section, component, asset, interaction, and responsive requirements.
- Acceptance criteria covering accessibility, performance, originality, and handoff.

## Guardrails

- Do not use named brands as implementation shorthand.
- Do not hide missing content strategy behind decorative motion.
- Do not introduce a heavy rendering stack for an effect that simpler technology can deliver.

# Project Memory

- [kind:workflow] [area:dependencies] [topic:dependency-audit] Dependency installation is permitted for OpenCaw implementation and verification after a lightweight provenance, version, lifecycle-script, and vulnerability audit; reusable commands must remain non-self-installing.
- [kind:gotcha] [env:wsl] [env:windows] [topic:path-translation] OpenCaw validation can run under WSL while Node.js, Git, Playwright, and FFmpeg resolve as Windows executables; translate paths only at the runtime boundary and preserve already-native Windows paths.
- [kind:architecture] [area:memory] [tech:bash] Memory v2 keeps all memory artifacts under `<project-root>/.ai/`: always-loaded constraints in `SYSTEM_MEMORY.md`, tagged facts in `MEMORY.md`, and semantic structure in `REPO_MAP.md`.
- [kind:convention] [area:commands] [topic:path-boundaries] Commands that write project artifacts resolve the active project through `commands/lib/memory-common.sh` and fail closed when the repository boundary is ambiguous.
- [kind:workflow] [env:windows] [tech:powershell] Use `commands/install-windows-bash.ps1` to prefer existing native Git Bash, explicitly install Git Bash or WSL, and invoke the Bash scaffold; Linux and macOS do not use this bootstrap.
- [kind:bug] [area:media] [env:wsl] [env:windows] Under WSL on Windows, exact-line Bash checks of Git-managed Markdown may see a trailing CR from CRLF; normalize carriage returns before comparing headings or index entries.
- [kind:decision] [area:repository] [topic:git-history] Published branches and tags exclude demo/ as of issue #80; README.md uses the GitHub-hosted attachment, and future demo binaries must not be re-added to repository history.
- [kind:convention] [topic:corrections] [area:media] When a user requests removal of a configuration directory, inventory and relocate every tracked file and update every live reference; do not preserve a conceptual subset unless explicitly requested.
- [kind:bug] [area:memory] [tech:bash] When a Bash printf format begins with a hyphen, pass -- before the format; commands/append-debug.sh and commands/append-rules.sh require this for reliable context writes.
- [kind:convention] [topic:corrections] [area:documentation] When explaining OpenCaw to users, lead with ordinary natural-language collaboration and conversational planning; present named roles, skills, and commands afterward as optional precision controls.
- [kind:workflow] [area:gauntlet] [topic:critic-isolation] Gauntlet execution freezes a human-approved quality bar, records immutable real-artifact rounds from distinct fresh critics, preserves approved bar revisions, and requires current unit passes plus a fresh integration pass before completion.
- [kind:workflow] [area:gauntlet] [topic:pr-delivery] Gauntlet work uses `gauntlet/<name>` for a frozen-base, gapless `baseRefOid`→`mergeCommit` integration chain and `gauntlet-work/<name>/...` for unit PRs. Evidence binds matching fetch/push origin and same-repo PR identity, execution/scope/bar fingerprints, real refs, non-bot merges, semantic live QA comments, terminal replay, transitive causal remediation, and report-bound immutable completion; only promotion failure may consume completion, and promotion remains human-gated.
- [kind:workflow] [area:tooling] [topic:workspace-boundaries] When repository work encounters host disk pressure, cleanup remains inside the resolved repository unless the user explicitly approves exact external targets; report an external storage blocker instead of clearing global caches or temp data.
- [kind:architecture] [scope:core] OpenCaw uses optional explicit persistent Brainstorm discovery before planning, then task mode by default or explicit Goal/Gauntlet delivery; Brainstorm creates no delivery artifacts and exit only generates its summary index.
- [kind:workflow] [area:brainstorm] [topic:idea-discovery] Brainstorm keeps stable branches and fully researched ideas in repository-root BRAINSTORM.md, uses one project-manager plus two read-only researcher subagents, blocks delivery creation while active, and generates hash-bound BRAINSTORM_SUMMARY.md only on explicit exit.
- [kind:architecture] [area:skills] [area:roles] Rigged runtime actor preparation is owned by prepare-rigged-runtime-actors and arts/technical-3d-artist, with opencaw-rigged-actor/v1 enforced by commands/validate-rigged-actor-manifest.sh; scroll-authored narrative ownership remains with build-scroll-authored-web-experiences and its existing web-role mappings.
- [kind:workflow] [area:skills] [topic:dependency-audit] Capability adaptations are dispositioned in skills/EXTERNAL_SOURCES.md; retained guidance must remain independently authored and exclude source identities, code, payloads, project identity, and publication workflows unless attribution is legally required.
- [kind:architecture] [area:skills] [area:roles] Blender 4.5 art production is owned by arts/blender-production-artist and eleven stage-specific skills from direct-blender-production through review-blender-deliverables; existing STYLE.md, MEDIA.md, runtime handoffs, staging, and human review remain authoritative.
- [kind:command] [area:commands] [topic:path-boundaries] [tech:bash] Blender production commands provide deterministic briefs, read-only repository-confined 4.5.x scene inspection, opencaw-blender-scene/v1 validation, and parse-only restricted bpy review with exact-content SHA-256 binding.
- [kind:workflow] [area:repository] [topic:corrections] Treat direct selection of existing architecture or style templates as trivial configuration: skip task and issue creation, regenerate only the requested contracts, and use targeted contract validation unless broader validation is independently warranted.
- [kind:architecture] [area:media] [area:styles] Art production uses first-class CLOUD, LOCAL, CSS3, CODE, and BLENDER contracts under .styles/.pipelines; generated STYLE.md defaults to CSS3, prompt overrides are task-local, and selected-pipeline failure never permits silent fallback.
- [kind:convention] [topic:corrections] [area:styles] When changing a complete art-pipeline registry, inventory established production systems such as Blender alongside newly requested mechanisms so contracts, routing, documentation, and tests stay complete.
- [kind:architecture] [area:styles] [area:assets] STYLE.md may optionally configure named absolute external 3D asset-library roots; libraries are read-only, are searched before replacement creation/download, and selected assets must be copied into assets/models/<library-id>/ before any load, import, edit, or use.
